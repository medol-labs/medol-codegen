# Simulation 业务旅程验收设计

本文维护 MEDOL、Code Generator 和 Simulation 之间的设计契约。各仓库的 TODO 追踪实施进度。文中描述的是目标行为，当前以 Simulation 的 `schemaVersion: 2` 执行器、用例审核和环境登记为基础。

## 职责与数据流

| 组件 | 职责 | 产物 |
| --- | --- | --- |
| MEDOL | 在工作区的「旅程验收」页面编写、同步和审核常规用例。引用指定版本的模型元素。 | 旅程用例、参数组、审核快照 |
| Code Generator | 为选定的应用代码产物输出接口契约。应用项目可使用编译器，把审核用例转换为该应用可执行的计划。 | 应用接口契约、执行计划、用例行与执行步骤的对应关系 |
| Simulation | 绑定环境和身份，执行准备流程、业务动作和断言，保存运行证据。 | 运行标识、阶段结果、证据和失败诊断 |
| Operations 与项目扩展 | Operations 描述部署。项目提供环境清单、数据资产、准备流程及重启等专用适配器。 | 在运行时解析的服务位置、工作负载实例及测试资源 |

数据流为「MEDOL 导出模型与审核用例 → 各应用项目结合自己的接口契约编译计划 → Simulation 选择部署并执行」。旅程用例是工作区制品，可单独导出，也可随工作区导出。现有 slice `specification` 继续验证 slice 的行为；旅程用例引用相关 slice 和 spec，验证跨 slice、部署和身份可观察到的结果。工作区表格提供这些表达，继续使用现有 MEDOL DSL。

## 模型用例如何交给应用项目

一个模型版本可以生成多套应用代码，同一份审核用例也可以交给多套应用。MEDOL 只掌握模型快照、业务元素引用、用例、参数及审核记录。应用代码仓库、生成目标、接口契约和部署实例都由应用侧管理。MEDOL 导出时无需选择应用，也无需访问应用代码。

### 导出与模型配对

| 导出文件 | 内容 |
| --- | --- |
| `codegen-model.json` | 现有生成输入及其来源信息。 |
| `journey-cases.json` | 独立版本化的用例导出物。每份文件对应一个已保存的模型快照，记录工作区和模型版本标识、源模型 SHA-256，以及所选的已审核用例版本、审核快照、参数声明和可选的参数组版本。 |

MEDOL 可以一次下载两个文件，也可以仅导出用例。配对使用 `codegen-model.json` 来源信息中的源模型 SHA-256，同一工作区的版本标识用于确认和追溯所选快照。模型内容指纹以源模型为准，导出格式、翻译和 JSON 排版变化不影响配对。应用侧在编译前核对来源，来源缺失或内容不匹配时提示补齐或重新导出对应版本。

在 MEDOL「旅程验收」点击「导出用例」后，先选一个已保存的模型版本。用例列表只提供该快照对应的已审核版本，逐条显示名称、版本和审核状态，作者勾选要交付的版本。需要一起交付测试输入时，可以再勾选符合相应用例约束的参数组版本。导出前显示所选模型、用例和参数组的摘要，最后选择「仅下载用例」或「同时下载模型和用例」。导出文件只反映此次选择。

### 应用侧选用与更新

1. **首次生成 Simulation。**应用维护者将导出文件放入项目，在 Simulation 生成配置中显式声明用例文件路径以及要采用的用例 ID 和版本。执行现有生成命令时，先校验模型配对，再用该应用的接口契约和项目登记的准备流程编译所选用例，逐条报告结果。通过后输出 v2 计划并登记。无法解析的操作、字段或准备流程定位到具体用例行。未配置用例文件时沿用现有生成流程。
2. **只改用例。**在 MEDOL 审核新版本并只导出 `journey-cases.json`。应用维护者通过独立的导入入口预览，首版可用 CLI。预览使用项目现有的模型、接口契约和准备流程，复用首次生成的校验与编译逻辑。维护者确认采用通过校验的用例后，保存对应计划并更新目录指向。只换符合约束的参数组时，可直接复用原计划。
3. **保留历史。**项目默认目录为每个用例指向一个当前版本。新计划按来源用例版本和计划指纹独立保存，重复导入同一计划复用已登记的产物。切换目录指向时保留旧计划及其审核、契约和运行记录。按原版本重跑时显式选择对应的历史计划，并重新校验目标部署。

导入预览逐条显示用例名称、当前版本、导入版本和结果。结果包括新增、可升级、已存在、无法编译。无法编译时显示原因和对应行。预览期间目录保持原样，维护者可以缩小采用范围再确认。确认时若当前目录或接口契约已变化，重新预览后再采用。被阻塞或未选中的用例保留原有目录指向。

同一个「提交任务并等待完成」用例可以分别编译为应用 A 和应用 B 的计划。两份计划共享来源用例 ID 和版本，各自记录应用产物、契约和计划指纹。A 可以先采用新版本，B 继续使用旧版本。业务部署和具体服务实例在发起运行时选定，写入本次运行记录。

## 用例编写与版本

一个用例描述一个验收目标，包含稳定的用例 ID 和版本、绑定的模型版本、步骤表、预期表、参数声明和来源。参数组提供类型化的具体值，可单独保存和版本化。参与方数量是参数，资源与实例分布由目标环境提供。验收规则本身不同的场景使用独立用例。

- **步骤表**选择已建模的操作或登记的准备流程。输入可使用类型化常量、参数组值、前序步骤的输出或当前集合成员。作者看到业务字段名和来源，编译产物包含实际请求参数和引用路径。
- **预期表**选择观察对象及业务键，声明唯一记录、记录数量、字段比较或逐项检查。两侧可分别引用已定位记录的字段。每项断言选择立即检查、有界等待或持续观察。
- **模型同步**根据显式命令、事件、自动化关系、字段映射和 slice spec 产生候选草稿。自动化触发的命令由被测系统执行。真实准备数据、跨步骤的业务预期及时间限制由作者补齐。重新同步显示新增和失效引用，保留人工编辑；元素引用失效后由作者重新绑定。
- **审核快照**记录审核人、审核时间、用例版本、内容指纹和模型快照。修改验收逻辑、模型绑定或允许的参数范围时，创建新用例版本并重新审核。参数组独立版本化，运行时按审核过的类型和范围校验实际值。

审核、产物校验和运行授权分别处理。审核确认用例与验收预期，指纹检验内容是否变化，运行授权由 Simulation 按本次调用者、目标环境、业务身份及具体动作判断。运行前校验审核快照来源、计划是否对应该快照，以及调用者是否有权使用本次绑定的环境和身份。环境策略要求确认时，确认绑定本次计划、参数和部署。查询运行详情、撤销及重新发起也应按各自权限校验。

既有手工计划保留原入口和审核规则。项目特殊用例按所需操作选择维护位置，见下文。

## MEDOL 端交互

「旅程验收」是 MEDOL 工作区中与「建模」并列的独立页面，沿用工作区切换和模型版本选择。左侧列出用例，支持新建和从所选模型版本同步候选草稿。右侧显示所选用例绑定的模型版本、审核及可执行状态，并提供「用例」「参数组」「执行记录」三个页签。模型引用可以跳回相关 slice。

**用例以业务选择为主，纯文本只用于书写验收意图。**标题、目标、背景和备注可以自由撰写；实际执行哪些操作、使用哪些数据以及通过条件是什么，都由结构化选择和类型化输入决定。例如，作者可以手填一个预期状态值，但需要先选定要检查的读模型和状态字段。表格按业务语言展示每行含义，点开行详情可以查看和修改绑定。

| 阶段 | 作者怎么选 |
| --- | --- |
| **Given · 步骤表** | 添加前置检查或准备步骤，选择可复用的准备流程或用于核验的读模型。明确复用已有数据还是创建本次数据，填写类型化参数，并选择要供后续步骤引用的输出，例如本次任务 ID 或参与方列表。 |
| **When · 步骤表** | 从所选模型版本的命令目录选择业务动作。参数可以直接填写，也可以绑定参数组值或前序步骤输出。例如选择 `SubmitTrainingJob`，把任务 ID 绑定到 Given 准备的记录。 |
| **Then · 预期表** | 选择要观察的读模型，用业务键定位记录，再选择检查记录数、判断字段值、比较两条记录的字段或逐项检查集合。最后选择立即检查、期限内最终成立或在窗口内持续成立，并填写适用的时间限制。 |

例如，要验收「每个参与方第二轮使用第一轮的聚合模型」，先在预期表中按任务 ID 和轮次定位平台第一轮的唯一记录，再从 Given 的输出选择本次参与方列表，逐项定位各自第二轮的执行记录。字段比较的两侧分别选择第二轮的 `baseModelId` 和第一轮的 `aggregatedModelId`，要求两边均有值且相等。行详情保留定位条件和字段来源。选择器只展示当前步骤可引用且类型兼容的选项，缺少绑定或引用失效时在对应行显示诊断。

草稿可先校验，再审核一个确定版本。「运行」弹窗选择参数组版本和目标环境，并预览将执行的关键动作。目标环境未就绪时，弹窗显示阻塞原因，编写和审核仍可进行。「执行记录」按 `runId` 展示历次运行，点击后按 Given / When / Then 回看步骤，并展开各目标服务实例的证据。

## 项目特殊用例

维护位置由用例需要的操作决定。可以通过业务命令和读模型表达的项目专属规则，在 MEDOL 用步骤表和预期表编写并审核。例如，资源不足时提交应被拒绝，补充资源后再次提交应被受理。

需要控制服务、部署拓扑或故障时机的用例，由项目在 Simulation 中维护。例如，聚合完成后、回执返回前重启服务，再验证恢复后没有重复聚合。环境动作与业务断言放在同一个用例版本中，使用同一个 `runId` 记录故障是否发生、服务是否恢复及最终业务证据。项目维护用例和受信任的适配器，重新生成时保留这些文件。可复用的环境准备动作可以登记成有类型参数和输出的准备流程，供 MEDOL 的 Given 选择。适配器仍由 Simulation 项目维护。

### 模型关联与 MEDOL 查看

在项目用例目录中登记项目标识、用例 ID 和版本、名称、维护来源、关联的模型版本及元素 ID。模型版本对应具体快照，元素 ID 可以引用 context、slice、command、event、readmodel 或 specification。项目维护的执行计划记录该项目的接口契约。元素名称用于展示，引用校验以 ID 为准。模型升级后若引用失效，按行提示受影响的元素，由维护者更新绑定并重新审核；原审核版本与历史报告保留原始关联。

接入某个 Simulation 项目的用例目录或运行结果时，MEDOL 按其中的模型快照和元素引用定位对应的用例或 slice。项目用例在「旅程验收」以只读方式展示，标记「Simulation 项目维护」，并显示提供目录或结果的项目来源。该接入用于查看和发起运行，独立于模型与用例的保存、审核和导出。

### 统一执行

MEDOL 编写的用例与 Simulation 项目用例都通过同一个执行入口运行，提交项目与用例标识、已审核版本、参数组版本和目标环境。执行端按登记来源加载对应的审核计划，统一检查模型关联、环境就绪、执行权限及确认策略，并返回 `runId` 和同格式报告。涉及重启或故障注入时，还要校验目标环境已允许该动作，且调用者具备相应权限。MEDOL、CI 和 AI 都使用同一套规则。

## 接口契约与编译

模型提供命令、读模型、字段类型和元素 ID。目标生成器导出与实际接口一致的 HTTP 方法、路由、请求字段及编码、响应及分页结构、筛选能力和部署角色。执行前根据环境清单解析部署角色到实际服务或实例，按已配置的认证连接获取凭证。显式登记的项目扩展可以提供手写接口契约。

编译时检查模型版本、字段与操作 ID、类型兼容性、参数完整性、引用顺序、字段可观察性及执行器支持范围。无法绑定的用例行或断言应阻断执行，并报告缺失的契约。生成的 `command`、`query`、`assert` 和 `foreach` 沿用现有 v2 格式；新用例额外保留阶段、来源行和执行要求。旧计划按现有规则运行。

### 校验契约与实际部署

编译产物记录用例审核快照、模型版本、各部署角色使用的接口契约版本及指纹，以及计划指纹。接口契约与构建产物一同发布，部署清单记录各服务实例实际部署的制品标识（例如镜像 digest）及对应的契约指纹。手写接口和适配器也通过项目登记的制品与契约关联纳入校验。

Simulation 在执行 Given 之前，将计划要求的契约与目标部署快照逐个核对，并通过部署探测确认实际实例仍与快照一致。对于执行中才解析出的目标，在首次调用前完成同样校验。首版按契约指纹精确匹配。探测应包含实例或制品身份以及就绪状态，普通健康检查只提供就绪证据。遇到缺少证明、指纹不符或部署已变更时，标记为阻塞，报告用例行、部署角色、实例和期望／实际版本。维护者可以选择匹配部署，或针对新契约重新校验并编译，涉及审核内容变化时重新审核。运行中若发现已绑定部署发生变化，停止后续操作并保留已有证据。

## 执行与判定

| 阶段 | 执行规则 | 关键结果 |
| --- | --- | --- |
| Given | 核验前置条件，显式选择复用已有数据或创建本次专属数据。保存数据来源、环境和业务 ID。 | 已就绪、前置阻塞、准备失败 |
| When | 通过正常业务接口执行关键动作，记录本次调用和回执。动作被跳过时记录未验证；写请求超时或回执丢失时记录结果未知，转入对账或显式恢复。 | 已受理、符合预期的拒绝、动作失败、结果未知、未执行 |
| Then | 只读查询或通过支持的观察适配器取证。按预期核验业务完成、用户可见投影或其他明确事实。 | 通过、断言失败、观测失败、超时 |

立即检查对一次有效观测判定。最终成立在指定期限内轮询，首次有效观测满足条件时通过，可配置明确的终止失败状态。持续成立要求在指定窗口按约定间隔完成观测，任一有效观测违反条件即失败，观测中断单独报告。持续成立的证据范围以实际采样为准。

唯一记录断言按完整匹配集判断，使用接口提供的精确总数或有界读取完整结果。记录缺失、重复、字段为空、字段不匹配分别报告。集合断言记录预期范围和实际检查对象，空集合只有在显式允许时才能通过。等待只重复观测，命令的恢复与重试由单独的用例或准备流程明确表达。

## 用例、执行记录与服务实例

一个业务旅程用例可以有多次执行。同一个已审核版本也可以重复执行。每次独立的运行意图创建一条执行记录，由 Simulation 在开始执行前统一分配并持久化对外 `runId`。记录固定用例版本、参数组版本和实际参数、目标环境标识、部署快照及计划指纹。环境准备、执行器任务和报告都关联这个 `runId`，各组件已有的内部任务标识可保留用于追踪。业务数据引用、结果和报告按 `runId` 保存，历史记录保留原来的绑定与证据。

| 发起方式 | 新执行记录如何保存 |
| --- | --- |
| 换参数组 | 绑定所选参数组及其版本，保存本次生效的参数值。沿用同一已审核用例及验收预期，按新参数校验前置条件。 |
| 换环境 | 绑定所选目标环境和本次部署快照，在该环境重新解析服务实例、身份和准备数据。旧环境的运行与报告仍归属原记录。 |
| 按原配置重跑 | 沿用原记录的用例版本和参数组版本，核对原目标环境及部署快照，创建新 `runId`，并记录来源运行 ID。部署快照已变化时，应以当前部署发起新运行并记录实际绑定。重跑重新核验 Given，按用例规则复用合格的准备数据或创建本次数据。若上次写操作结果未知，先对账，再决定后续操作。 |

一次运行可以调用多个实际服务实例，例如一个平台服务和各参与方的 Runtime Agent。它们共享同一个 `runId`。报告在该次运行下按步骤和目标实例记录证据，包含部署角色、实例标识，以及适用的参与方或业务记录标识。各参与方的断言结果汇总为该次运行的用例判定。任一必检实例的断言失败，该次用例即失败。

## 运行入口与证据

人工、CI 和 AI 使用同一个入口，提交用例 ID 与版本、参数组版本和目标环境标识，获得运行 ID。执行前重新校验审核快照、接口契约、环境就绪和调用权限。有副作用的操作遵循目标环境的确认策略。AI 可以提出草稿、选择已审核用例和解释报告。

每次发起意图使用一个请求标识。页面重复点击、客户端超时或响应丢失后的重试复用该标识。Simulation 在项目和调用者范围内原子登记请求标识与请求内容、`runId` 的对应关系。相同标识和内容再次到达时，经访问校验后返回已登记的 `runId` 和当前状态，执行侧只领取一次该次启动任务。相同标识携带不同内容时返回冲突。记录已创建但运行尚未开始时，恢复同一条待执行记录。运行器中断且已有写操作的结果未知时，按对账规则处理。用户主动重跑使用新请求标识，创建新 `runId` 并关联来源。此规则覆盖验收发起请求，业务命令仍按自己的结果及恢复策略处理。

报告按 Given / When / Then 展示用例行、阶段、执行状态、耗时和脱敏证据，并关联模型版本、用例与计划指纹、参数组及环境。区分静态校验、真实运行、显式跳过和因前序失败而未执行。失败证据至少包含业务键及适用的期望值和实际值。凭证留在运行环境，输出字段按证据白名单保存。清理以本次登记资源为范围，失败环境默认保留以便诊断。

## 首版实施范围与验收

1. **定义并编译制品。**定下旅程用例、参数组、审核快照、生成接口契约和运行记录。先用参考旅程验证从业务字段绑定到 v2 执行计划的转换，并让执行计划可追踪到用例行。
2. **接通 MEDOL 编写与审核。**实现独立页面、Given／When 步骤表、Then 预期表、参数组、行级校验和审核。首版预期表覆盖按业务键定位、唯一性与计数、字段比较、逐实例检查和有界等待。支持列出项目维护的已审核特殊用例并只读查看。
3. **接通真实运行和证据。**在现有 Simulation 执行入口上提供发起与查询能力，校验实际部署与运行权限，保存统一 `runId` 并处理重复请求。MEDOL 可在离开页面后按运行记录继续查看结果。现有手工计划继续经原入口运行，重新生成时保留手工用例。

以两轮训练中的模型继承作为首条参考旅程，参与方数量由参数组提供。Given 准备可训练的参与方和一条新任务，When 调用 `SubmitTrainingJob`，Then 验证同一任务达到 `Completed`。按任务 ID 和轮次定位唯一的平台记录，再按任务、第二轮和运行时 ID 定位各参与方的唯一执行记录。比较各参与方第二轮的 `baseModelId` 与平台第一轮的 `aggregatedModelId`，要求两边均有值。错误模型、缺失记录和重复记录均需给出具体的参与方、轮次及失败原因。

首版完成以作者能从 MEDOL 编写、审核并运行参考旅程为准。正例通过，错误模型反例给出参与方、轮次和差值证据。验证还须覆盖越权或契约不一致时执行前阻塞、并发提交同一请求只发起一次、新请求重跑保留旧证据、投影延迟、关键动作跳过和写请求结果未知。持续成立的观察能力、质量门禁和集中运行管理可在这条链路验收后分阶段接入。
