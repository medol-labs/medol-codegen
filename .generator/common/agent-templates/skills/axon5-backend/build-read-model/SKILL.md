# Build Read Model

Use this skill for read-side work: events -> projection state -> query endpoint
-> frontend resource data.

## Read First

- Read model definitions and subscribed events in `codegen-model.json`.
- Event payloads emitted by the write slices.
- Existing projection files and query controllers in the same context.
- Refine resource metadata when the read model is exposed in the UI.

## Projection Rules

- Subscribe only to events that exist in the model.
- Projection identifiers must be stable and derived from event identifiers.
- Preserve denormalized display fields when the read model asks for them, but do
  not use display fields as consistency identifiers.
- Value object fields should be stored/queryable according to the generated
  persistence pattern.
- Empty-state behavior belongs in query/frontend code, not event-sourced state.

## Query/API Rules

- Keep generated endpoint names and resource names stable.
- Match pagination and sorting conventions already generated by the backend.
- Return DTO fields that match the frontend generated resource schema.

## Verification

- Run backend compile/tests.
- Run frontend typecheck/build when resource schemas or list/show pages change.
